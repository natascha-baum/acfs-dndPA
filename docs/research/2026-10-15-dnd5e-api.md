# Research: D&D 5e API as data source

Date: 2026-10-15 · Phase: Research · Led to: [plans/plan.md](../plans/plan.md) sections 4 and 6

## Question
Where does the app get valid 5e game data (races, classes, spells, items) without writing it by hand, and what does it have to build itself?

## Findings
- **D&D 5e API** (https://www.dnd5eapi.co): free, no API key, REST and GraphQL, JSON. Open source (5e-bits/5e-srd-api), data from 5e-bits/5e-database.
- Content is the **SRD 5.1** under **CC-BY-4.0**: attribution is required (shown in the app footer and README).
- Base URL `https://www.dnd5eapi.co/api/2014/`. Endpoints the app needs:

| Endpoint | Used for |
|---|---|
| `races`, `races/{id}`, `subraces/{id}` | race list, ability bonuses, speed, traits, proficiencies |
| `classes`, `classes/{id}` | class list, hit die, proficiencies and choices, saving throws, starting equipment |
| `classes/{id}/levels/{n}` | ability score improvements, spell slots, features per level |
| `classes/{id}/spells`, `spells/{id}` | spell list per class, spell details |
| `equipment/{id}`, `equipment-categories/{id}` | items, armor class of armor, pack contents |
| `proficiencies`, `skills`, `traits`, `features` | detail lookups on the character sheet |

- **Choices** in the API (e.g. "choose 2 skills from …", starting equipment options) come as a nested `{ choose, from: { options } }` structure that has to be resolved recursively.
- **Limits:** SRD only (one subclass per class, 9 races, no backgrounds beyond Acolyte), English only. No names, personalities or scene content.
- No documented rate limit, but it is a free public service: responses should be cached.

## Consequences for the app
- Take everything rule-relevant from the API; build own tables only for flavor (names, personality, appearance, story hooks, scenes).
- Ability scores via the **standard array** (15, 14, 13, 12, 10, 8), placed by class priority: valid by the rules and reproducible.
- Cache responses locally (7 days) and share concurrent requests.
- Tests use real records from 5e-bits/5e-database as fixtures, so they run offline.

## Open questions (resolved)
- Point buy or rolling? → standard array (decision in the plan).
- Characters from outside the SRD (player sheets)? → upload the PDF, link spells to the SRD where they exist.
